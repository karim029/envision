## Decisions log

- 2026-11-15 — **Guiding principle:** production-grade habits, MVP-sized scope; build so it can scale, don't build for scale. — Learn real practices without over-engineering a 5–10 tester beta.
- 2026-11-15 — **Dropped `IdempotencyKey` table.** Finalize-once is enforced by the `IN_PROGRESS → COMPLETED` conditional `updateMany` (`count === 0` → already processed → `200 OK`). — The state machine already guarantees once-only; a second mechanism adds a table without adding safety. Revisit if an event type appears that has no state transition to guard it.
- 2026-11-15 — **Slimmed Chunk 0 CI** to `tsc`, `lint`, `test:unit`, `build`; web deploys via Vercel GitHub integration. Integration tests in CI, migration `deploy.yml` and Supabase keep-alive moved to Chunk 1. — Nothing to migrate or keep alive before the database exists.
- 2026-11-15 — **One CI job with sequential steps** instead of chained jobs. — Same fail-fast order, one `npm ci` instead of several. Split later only if it gets slow.
- 2026-11-15 — **CI concurrency group includes `github.event_name`.** — Without it, `push` and `pull_request` runs for the same branch share a group and cancel each other, leaving a "cancelled" check on the PR.
- 2026-11-15 — **Vitest path alias via `resolve.alias`** in `vitest.config.mts`. — Avoids adding `vite-tsconfig-paths` as a dependency.
- 2026-11-15 — **No in-app feedback** (`SessionFeedback` table and widget removed; `feedback_submitted` event dropped → 6 funnel events). — Beta feedback is collected verbally in meetings.
- 2026-11-15 — **Gemini Flash free tier** for candidate LLM and grading. — $0 stack. Caveat: free-tier content may be used by Google to improve products, so use synthetic/anonymised CVs until switching to a paid tier for real HR data.
- 2026-11-15 — **`src/` layout + Node 26 pin via `engines`.** Moved `app/` → `src/app/`, alias `@/*` → `./src/*`; `engines.node: 26.x`, no `.nvmrc`. — CLAUDE.md architecture is `src/`-rooted (server, worker, env live beside the app) and the move was free before imports existed. Vercel and `setup-node` both read `engines`, so it's one source of truth.
- 2026-11-15 — **Env validated at build time.** `parseEnv` uses `safeParse`, then throws one error listing every bad key as `key: message` (never the value). `src/env.ts` is imported in `next.config.ts`, so bad env fails `next build`. Rule: add a key in the same PR that first reads it. — A broken config should block the deploy, not surface as `undefined` in production; one error with all issues means one fix per redeploy; values may be secrets, so they never reach logs.
- 2026-11-15 — **Prettier with defaults** (`.prettierrc.json` is `{}`), `format` / `format:check` scripts; `format:check` runs in CI. No `eslint-config-prettier`: the Next ESLint config has no formatting rules, so there's nothing to conflict with. — Consistent style and diffs that show logic, not whitespace. Defaults already match the create-next-app style (double quotes, semicolons, 2 spaces).
- 2026-11-15 — **LF line endings enforced** via `.gitattributes` (`* text=auto eol=lf`). — CI and Vercel run on Linux; stops Windows `core.autocrlf` from producing CRLF churn.
- 2026-11-15 — **Vercel preview protection kept on;** previews are checked in a logged-in browser, not with `curl`. Keep-alive (Chunk 1e) calls the production URL. — Previews will expose real features; production is unprotected by default.
- 2026-11-15 — **Databases:** local Docker Postgres 17 (`docker-compose.yml`, port 5433) for dev (`envision`) and tests (`envision_test`); one hosted Supabase project for the real app + Auth, which only receives migrations via `migrate deploy`. Supabase URLs never go in local `.env`. — Fast, disposable tests that can't touch real data; same migrations everywhere prevent drift. Revisit (second Supabase project for dev/preview) when testers have real data.
- 2026-11-15 — **Prisma pinned to exactly `7.10.1`** (`prisma`, `@prisma/client`, `@prisma/adapter-pg`). — npm's `latest` tag for `prisma` points at a v8 release candidate that doesn't match the v7 client.
- 2026-11-15 — **RLS on every table + Supabase Data API turned off.** RLS is enabled by hand in each migration (no policies = REST API sees nothing; Prisma connects as owner and bypasses it); `tests/integration/rls.test.ts` fails if a table is missed. — Supabase exposes the `public` schema over REST with the browser-visible key; leaving RLS off would leak every tenant's data. Data API off is the main fix, RLS is the second layer.
- 2026-11-15 — **Minimal columns per chunk.** The init migration has only today's fields; later chunks add theirs with their own migrations. — Migrations are built for growth; guessing Chunk 4–5 columns now means migrating them again anyway.
- 2026-11-15 — **Integration test harness:** Vitest `unit` + `integration` projects; integration runs files serially, migrates `envision_test` in global setup, truncates all tables before each test, and refuses any database whose name doesn't end in `_test`. CI runs it against a `postgres:17` service container. — Concurrency, transactions and constraints only exist in a real database; the `_test` guard makes wiping real data impossible by misconfiguration.
- 2026-11-15 — **`tsx` for TypeScript scripts** (`scripts/*`, later the Chunk 4 worker). esbuild's install script is denied (not needed on supported platforms). — Node can't resolve the `@/` alias on its own.
- 2026-11-15 — **Single-use invite links instead of a shared `INVITE_CODE`.** New platform-level `Invite` table (`tokenHash` = SHA-256 of a 32-byte base64url token, `label`, `expiresAt` default 14 days, `usedAt`, `usedByTenantId`). The owner creates links with `npm run invite:create -- "<who>"` (refuses a non-local DB without `--yes`). `onboardTenant` claims the invite with a conditional `updateMany` (`count === 1`) in the same transaction as the Tenant + User inserts. Invites are not bound to an email (`label` records who it was for). — Testers will be cold-invited HR people we don't know personally: a shared code would be forwarded with no way to tell who leaked it or revoke one person. Removal path after the beta (public signup + payment gate): drop the claim step + one migration dropping `Invite`; it can also evolve into tenant team invites by adding `tenantId`.
- 2026-11-15 — **Owner tooling = scripts for now.** Owner powers never come from tenant `role = ADMIN` (every customer's first user is ADMIN); a future owner admin uses a separate owner check. — A CLI is enough for one person sending invites.
- 2026-11-18 — **`onboardTenant` = retry check → interactive `$transaction` (claim invite via `updateMany` + `count` check → create Tenant → create User → set `usedByTenantId`) → on `InvalidInviteError`, re-read the user ("on conflict, re-read").** Only `InvalidInviteError` with an existing user is handled; every other error is rethrown unchanged. — Interactive (not batch) because later steps need `tenant.id` and the claim's `count` decides whether to continue. The re-read makes a same-user double-click return `created: false` instead of "invalid invite": under READ COMMITTED a concurrent request can't see the winner's uncommitted user, but by the time its claim fails the winner has committed. Rethrowing unchanged keeps "email already registered" and DB outages from masquerading as invite errors (tested).
- 2026-11-18 — **Invite token encoding via `Buffer.toString("base64url")`,** not `Uint8Array.prototype.toBase64`. — Node 26 has `toBase64` at runtime, but TypeScript 5.9 / `@types/node` don't declare it, so tests passed while `typecheck` and `build` failed. Lesson: run the full CI checklist (format, lint, typecheck, unit, integration, build) before committing — Vitest strips types without checking them.
- 2026-11-22 — **Signup flow (Slice 1d):** `onboardTenant` runs right after Supabase `signUp` (not after email confirmation); a read-only `checkInvite` pre-check runs before `signUp`; Supabase's fake-user response for an already-registered email is detected before onboarding; a login with no `User` row is sent to `/onboarding`. — Everything needed is still in the signup form, so nothing has to survive across requests or devices. Cost: a mistyped email uses up an invite (owner sends a new one). The pre-check stops bad links before creating a Supabase account; the atomic claim stays the real guarantee.
- 2026-11-22 — **Auth context split:** `getAuthContext(authUserId)` service (DB lookup → `ok` with `{ userId, tenantId, role }` or `needs_onboarding`; integration-tested) + thin `requireAuthContext()` wrapper (`getClaims()` → redirect `/login` / `/onboarding`; `server-only`). `tenantId` and `role` come from our DB, never from the token. — The decisions are testable without a browser session; the wrapper is glue, verified manually end-to-end.
- 2026-11-22 — **`/auth/confirm` with `verifyOtp({ type, token_hash })` instead of `/auth/callback` + `exchangeCodeForSession`.** Accepts only `type` = `email` (signup → `/dashboard`) or `recovery` (password reset → `/account/update-password`); **no `next` parameter** — the destination is fixed per type. Requires the Supabase "Confirm signup" and "Reset password" email templates to link to `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=…`. — Supabase docs: the PKCE code exchange "must be initiated on the same browser and device where the flow was started", so confirming on a phone after signing up on a laptop would fail. Supabase's sample redirects to an unvalidated `next` (an open-redirect risk); we have no use for a custom destination, so dropping `next` removes the risk instead of guarding it. Add it back, with an allow-list guard, only when a real need appears (e.g. "return to the page you were on").
- 2026-11-24 — **Claude Code workflow reworked.** CLAUDE.md slimmed to ~65 lines of always-true rules; the chunk plan moved to `docs/BUILD_PLAN.md`. Work is split into ownership zones: a _learn zone_ Karim writes (`src/server`, `src/app`, `src/worker`, schema, migrations, first use of any Next.js pattern) and a _delegate zone_ Claude may write (config, CI, scripts, shadcn markup, patterns marked `owned` in `docs/LEARNING.md`). `.claude/settings.json` enforces it: edits in learn-zone paths prompt for approval; `prisma db push`, `git commit/push` and `.env` reads are denied. Per-task rituals became manual skills: `/status`, `/kickoff`, `/hint` (5-level ladder), `/review`, `/decide`, `/ship` (full check + commits + PR + teach-back). Commit at every green step; PRs ≤ ~300 changed lines, one concern; tooling/docs in their own PR. CLAUDE.md imports Next's `AGENTS.md` so Claude reads the Next 16 docs in `node_modules` before writing or explaining Next code. Output style: built-in Learning. — CLAUDE.md is context, not enforcement, and long files are followed less reliably; the zones let speed grow with mastery instead of trading learning for speed. Revisit if the Learning style gets too verbose (drop `outputStyle`) or the ask-prompts get in the way of delegate work.
- 2026-11-24 — **PR size rule: one concern per PR, ~≤ 400 changed lines excluding tests** (was ≤ 300 including tests). The split is decided at `/kickoff`, not after the work is done; a cohesive flow is never split just to hit the number. — SmartBear/Cisco review data shows defect-finding drops past ~200–400 lines, and Google's small-CL guidance puts "one self-contained change" above any line count. Tests are cheaper to review than logic. A post-hoc split of the login → dashboard → logout loop would have left `main` with a login that 404s, for little review benefit.
- 2026-11-24 — **Logout = Server Action (`<form action>`, a POST) + `signOut({ scope: "local" })`; a `signOut` error is ignored.** — With the default `global` scope, a failed network call keeps the session cookies, so a user redirected to `/login` would still be logged in (bad on a shared HR office computer). `local` removes the cookies first and revokes the refresh token best-effort, so "logged out" is always true in this browser. Logging out of all devices is parked in the backlog.
- 2026-11-24 — **Protected pages = sync static shell → async loader in `<Suspense>` (`requireAuthContext()` + service) → visual view; `requireAuthContext()` starts with `await connection()`.** — With Partial Prefetching, Next renders cookie-derived session data at prefetch time, and `getClaims()` compares the JWT's `exp` to `Date.now()`; without the guard a validity answer could be computed during a prefetch and reused after expiry (Next raises `blocking-prerender-current-time`). Putting it inside `requireAuthContext()` (not at module top level, which runs at import with no request and broke `next build`) protects every future page and action; in Server Actions it continues immediately.
- 2026-11-24 — **Tenant-scoped reads filter on `id` + `tenantId` and throw on a miss** (`getAccountSummary` → `AccountNotFoundError`), each with a cross-tenant integration test. — A miss right after `requireAuthContext()` means a bug or a tenant mismatch, so the page must not render half-empty; the cross-tenant test fails if a future edit drops the `tenantId` filter.
- 2026-11-25 — **Supabase Auth is beta-only; it will be replaced by auth we own after the beta** (how: D10). Until then, every Supabase call stays behind our adapters (`src/lib/supabase/*`) and injected ports (`signUpWithInvite(fields, { signUp })`); services never see Supabase types. — Karim wants full control of auth and no long-term vendor lock-in. The swap then touches only the adapters, `getClaims()` in `requireAuthContext()`, `src/proxy.ts`, `/auth/confirm` and logout; services and their tests stay. Known coupling: `User.id` = Supabase user id (one migration). Rule until the swap: no new Supabase-only features (MFA, OAuth, magic links) unless a tester needs them.
- 2026-11-25 — **`/onboarding` is a locked page, not a recovery flow.** It tells a logged-in user with no `User` row to contact whoever invited them, with a Log out button. A stuck tester is fixed by hand: delete their Supabase auth user, they sign up again with the same link (the invite claim rolled back with the failed transaction). — Only reachable after a rare race (`invite_claimed_meanwhile`) or a direct call to Supabase's public signup endpoint; a self-service flow (paste a new link, or compensation) costs days on a system that only lives through the beta (see above).
- 2026-11-25 — **Password reset parked until Chunk 6;** until then the owner resets passwords from the Supabase dashboard. — Testers aren't onboarded before Chunk 6, and reset would be built twice (Supabase now, our own auth after the beta).
